## Key Fields

- **user_id** (UUID, PK, FK) - Links to users table
- **role** (VARCHAR(50)) - Admin role type (e.g., SUPER_ADMIN, ADMIN, MODERATOR)
- **permissions** (JSONB) - Flexible JSON structure for access controls
- **created_at** (TIMESTAMP) - Record creation timestamp
- **updated_at** (TIMESTAMP) - Record last update timestamp

## Admin Roles

Suggested role hierarchy:

| Role | Description | Typical Permissions |
|------|-------------|---------------------|
| **SUPER_ADMIN** | Full system access | All resources: CRUD + system management |
| **ADMIN** | User and content management | Users, bills, reports: CRUD |
| **MODERATOR** | Content moderation | Users/bills: Read, support tickets |
| **SUPPORT** | Customer support | Read-only + ticket management |

---

## Permissions Structure

The `permissions` field uses JSONB for flexible access control:

```json
{
  "users": ["create", "read", "update", "delete"],
  "bills": ["read", "update", "delete"],
  "reports": ["read", "generate"],
  "system": ["manage_settings", "view_logs", "backup"]
}
```

### Benefits of JSONB:
- ✅ Flexible permission structure
- ✅ No schema changes needed for new resources
- ✅ Powerful query capabilities
- ✅ Index support for performance
- ✅ Easy to extend per-admin permissions

## Design Differences

### Admin vs Client/Consultant

| Feature | Clients/Consultants | Admins |
|---------|-------------------|--------|
| Tax ID | CPF/CNPJ (fixed field) | ❌ None |
| Address | ✅ Full address structure | ❌ None |
| Permissions | ❌ None | ✅ JSONB flexible |
| Role | ❌ None | ✅ Role field |
| Document Validation | ✅ Check constraints | ❌ None |

**Why Simpler?**
- Admins are internal users
- Don't need personal/company documents
- Don't need address information
- Focus is on permissions and access control

## Example Usage

### Query admins by role:
```sql
SELECT u.email, u.name, a.role
FROM users u
JOIN admins a ON u.id = a.user_id
WHERE a.role = 'SUPER_ADMIN';
```

### Query admins with specific permission:
```sql
SELECT u.email, a.role
FROM users u
JOIN admins a ON u.id = a.user_id
WHERE a.permissions @> '{"users": ["delete"]}'::jsonb;
```

### Get all permissions for an admin:
```sql
SELECT u.email, a.role, a.permissions
FROM users u
JOIN admins a ON u.id = a.user_id
WHERE u.email = 'admin@example.com';
```
